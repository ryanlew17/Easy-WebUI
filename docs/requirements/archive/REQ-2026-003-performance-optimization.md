# REQ-2026-003：安全修复后的性能评估与深度优化

状态：done（2026-11-02）
来源：REQ-2026-001 至 REQ-2026-002 的修复与项目内性能评估
关联设计：`docs/design/security.md`、`docs/design/chat.md`、`docs/design/message-tree.md`、`docs/design/storage.md`
影响模块：`electron/`、`src/`、`shared/`、`scripts/`、`tests/`
非目标：降低安全限制、缓存明文密钥、更换框架/数据库及无测量依据的 worker 或虚拟化改造

## 背景

安全修复后仍存在重复解密、首屏包体偏大、流式重复渲染、消息树 N+1 查询和备份长链退化。目标是在安全语义不变的前提下优先提升时间性能，并改善空间占用。

## 方案要点

- 建立隔离、可重复的主进程、渲染和 Electron 冷启动基准。
- 拆分启动依赖，条件回写旧密文，定向更新并记忆化流式渲染。
- 共享消息树索引，线性化备份与 SSE 路径，按文件元数据复用安全缓存。

## 验收标准

- 保留 IPC、协议、脱敏、备份、密钥和消息树安全不变量。
- 冷启动 <3s；1 万消息子树及删除操作 <500ms；流式脚本耗时下降 ≥40%。
- preload <100KB，异步加载和真实 Electron 行为正常，完整回归通过。

## 验收记录

2026-11-02 项目内自评估通过。

- 实现：完成启动拆包、密文回写、渲染去重、共享索引及备份/网关线性化。
- 验证：流式中位数 747.11ms → 97.89ms，子树 p50 6333.18ms → 7.73ms，preload 764936B → 6106B；冷启动最慢 1206.48ms。302 项测试、类型检查、构建、UI 和真实应用冒烟通过。
- 边界：250% 三栏全开的小宽度溢出为既有布局限制，不属于本需求修复范围。
